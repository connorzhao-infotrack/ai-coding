Automation Plan — three routes to the same goal
How to make the dashboard refresh itself every week, keep the written support summary you produce today, and still let you enter & fix records by hand. The routes differ only in how much AI does vs. how much you build.

The objective driving this
"Leverage AI to fully automate tracking & reporting for at least two key business metrics."
The two metrics: Releases (deployment / DORA) and Support (inbox volume + the weekly summary). Win condition = maximum automation with no human typing for the parts AI can do — while never losing what the report gives you today.
What every route must deliver (no regression on today's output)
⏱ Weekly auto-refresh+ Releases from Azure DevOps+ Connect to Outlook → all emails→ Counts + the written weekly summary+ ✍ Manual add/edit (hotfixes & fixes)
The summary is not just counts — it reads the full email content and condenses it with your taxonomy & chain-dedup, exactly like your current …-summary.md. That is why every route includes an AI step, not just a tally.

Cost reading — the token math (so it's not hand-wavy)

The weekly support job ≈ 35K input tokens (60 emails + taxonomy rules) + ~3K output for the summary. As a single API call:

R3 Azure — cheapest to run

Pays roughly the single-call number above → ~$1/month in AI, plus ~free Azure compute. But you build & own the software.

R1 Claude routine — cheapest to start

An agentic run uses 5–10× raw tokens (tool calls, reasoning) → ~$5–15/mo metered — or $0 marginal if it draws from a Max/Team plan you already pay for (counts against quota + a daily routine cap a weekly job never hits).

R2 Power Platform — least predictable

Token fee is tiny (~$1/mo on Azure OpenAI), but the real cost is fixed licensing — Power Automate Premium and possibly AI Builder credits — not tokens.

Billing model for R1

A routine run consumes tokens like any session. On a Claude subscription it's included in your usage allowance; on API/Console it's metered per-token. Never free, never on Anthropic.

Rules that apply to all three (so manual + auto never fight)

Hotfixes are yours

Change-failures are entered by hand. Mark them manual + locked; the weekly job never writes hotfixes — it's your primary input for them.

A manual edit always wins

Every row carries source (auto / manual) and locked. Correct a number and the next refresh leaves it alone — or flags a mismatch — instead of overwriting you.

Keep the summary, don't shrink it

The summary reads full email content + your taxonomy + chain-dedup — same as today's …-summary.md. Counts feed the charts; the narrative is kept as a file and can also show as a dashboard panel.

Routes can combine

Not all-or-nothing: e.g. Power Automate can do the Outlook pull (no app reg) and hand the emails to the Claude skill for the summary. Same data model underneath, so mixing — or moving up later — isn't a rebuild.

Recommendation

Start with Route 1 (Claude routine) — it's the most direct path to "AI fully automates it," reuses the skill that already writes your summary, and asks IT for almost nothing.

  1. Schedule the existing skills as a weekly Claude routine: pull releases from Azure DevOps + read the support inbox, classify, and write both the counts and your weekly summary.
  2. Drop the output where the dashboard reads it (a JSON file + the summary markdown) — and add a "Latest support summary" panel so the narrative shows alongside the charts.
  3. Add manual entry for hotfixes & corrections (a simple form or List) — locked so the routine never overwrites them.
  4. Stay flexible: if governance requires all-Microsoft, the same outputs come from Route 2; if you later need SLAs or untagged-email handling, graduate to Route 3. Same data model, so it's an engine swap, not a rebuild.
