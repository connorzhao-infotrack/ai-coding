What the industry converged on

Researched: ChatGPT Canvas, Claude Artifacts, v0/Bolt/Lovable/Replit, Copilot/Cursor, Intercom/Zendesk, BofA Erica, OpenAI Apps SDK, NN/g studies.

Every AI-native product uses one canonical canvas + reference chips (Variant A's shape): repeat requests focus/refresh the panel, never re-print. Zendesk/Intercom bake in lock-on-submit — a form becomes an immutable receipt (our booking flow). Claude/ChatGPT mobile = chip → full-screen/bottom sheet, composer kept reachable. NN/g documents the scroll-hunt pain ("apple picking") of long transcripts — the strongest evidence against re-rendering copies. v0 learned restore must be append-only after community backlash.

Problems → how we solved them

⚠ Same component re-rendered over and over

Older copies collapse to one-line stubs that jump to the latest — the transcript never fills with duplicates.

⚠ Scrolling up shows stale data as if current

Only the latest copy stays expanded and live (SignalR / refetch, subtle green dot). A superseded full view can't be misread.

⚠ "What if the user never clicks?"

The data comes to them: the live copy refreshes in place, the agent posts a short progress note, and single-route steps auto-advance.

⚠ Users don't know what to do next

Lexi's flow chart decides it: one outgoing arrow → the agent just does it; several arrows → pills docked above the input; orange loops → conditional re-prompts.

⚠ Every re-view used to cost an LLM turn

Milestone clicks render straight from the API — no chat turn, no tokens. (Full canonical-stage version is the post-project Variant A.)

⚠ Layout is approval-frozen mid-project

Every fix here is behaviour inside the approved layout — no Christian Beck round-trip needed.

⚠ New messages yanked the scroll position

Scroll is preserved on re-render — it only sticks to the bottom if you were already there.

The two questions from the ticket — answered

Q1 — When the user wants to see a component again (order details, a milestone), should we re-send a message that re-renders it?

No — open its one canonical view.

Viewing is not a conversation. A milestone click renders directly from the API into the pinned stage (instant, free, no transcript entry). Chat only gets a lightweight reference chip when the agent initiates a view.

Q2 — If components appear in history, do we keep them up to date, or lock them as a point-in-time record?

Views stay live · actions lock.

Every view is always-current (SignalR already exists). Every completed action — a booking, a submission, an approval — leaves an immutable receipt in the transcript. The DB + file notes remain the audit record, so the UI never has to be one.

What we established first (design interview)

Is there a compliance need to preserve exactly what was shown at a point in time?

No hard UI requirement. The old UI always shows latest; audit lives in the DB and agent-side file notes.

views can be live everywhere — snapshots become a choice, not a constraint

Must a milestone click go through the agent (predefined message → LLM → render)?

No — direct render is fine. The LLM is only needed when there is something to say or do.

viewing becomes instant and free; the transcript stops being the only render surface

How important is mobile?

Desktop-first; mobile must work well — practitioners at a desk, phone for checking on the go.

side panel on desktop + bottom sheet on phone is acceptable; permanent three-pane is not required

Where does this end up long-term?

The agent does more, the user reviews more. Less info flows through forms over time.

chat stays the primary surface; the workspace earns less screen as the product matures — disfavouring heavy three-pane

Evidence highlights

“Apple picking”

NN/g's study of daily chatbot users: people repeatedly scroll long transcripts to re-find earlier outputs. Duplicating components into the transcript makes the documented pain worse; chips + a pinned canvas attack it directly.

nngroup.com · accordion-editing-apple-picking

≤ ½ screen · ≤ 2 actions

Intercom caps every inline canvas at half the messenger; OpenAI's Apps SDK caps inline cards at two actions, no internal scrolling. Two vendors at scale independently concluded: rich content leaves the transcript.

developers.intercom.com · developers.openai.com/apps-sdk

Append-only restore

v0 shipped destructive version-restore, got sustained user backlash, and rebuilt it append-only ("restoring creates a new latest version"). If we ever show past component states, they must be read-only.

v0.app/docs/versions · community.vercel.com

Chat as router

Bank of America's Erica embeds nothing rich in chat — it deep-links to canonical screens, and users increasingly use it instead of menus. Matches the long-term goal: the agent does the work, the user reviews.

customerexperiencedive.com · americanbanker.com
